# 같은 기능의 다섯 표현을 모델이 같은 입력으로 읽게 하기

2026-10-10. 소형 결정 모델이 지역 변수 수나 반환식 모양의 차이를 다시 배우는 일을
줄이기 위해, 정적으로 확인 가능한 단일 분기의 값 흐름을 별도 입력 v5로 정리했습니다.
생산자는 SDK `3ecbcecdddd53b3e6e389e0004289c8e74409baf`, 실제 Gooo 파서는 컴파일러
`c6784f34e4ce9e208e53c361c757e04961233196`, 도구는 Go1.27.2입니다.

## 고정한 소스와 비교

최댓값·최솟값, 상수7·13·11·17, 원래 분기 방향2개, 한영 의도 표현2개를 조합해
논리 과제32개를 적었습니다. 각각 직접 반환·별칭·분기 대입·복사 뒤 덮어쓰기·분기 뒤
복사의 다섯 표현으로 구성해160개 Gooo 소스를 만들었습니다. 중첩 분기와 산술식
반환을 쓰는 별도 대조 소스2개도 포함했습니다.

같은 과제 안에서는 의도·선택지·출력8개·조건3개 사례가 같습니다. 다른 표현128개를
각 과제의 직접 반환 형태와 비교했습니다. [사전 계획](protocol.txt)을 먼저 커밋했고,
깨끗한 생산자로 전체 기록을 한 번 생성했습니다.

| 확인한 항목 | 결과 |
| --- | ---: |
| 같은 기능128쌍 중 v4 입력이 같은 쌍 |0/128|
| 같은 기능128쌍 중 v5 입력이 같은 쌍 |128/128|
| 같은 기능 쌍에서 통과 후보 집합이 달라진 경우 |0/128|
| 새 정리를 적용한 소스 |160/162|
| 원래 v4 입력을 그대로 유지한 대조 소스 |2/2|
| 동일 입력인데 통과 후보가 서로 겹치지 않는 쌍 |v4 0, v5 0|

각 소스의 후보4개를 모두 확인해648개 후보 기록, 출력5,184개, 조건 관측1,944개를
남겼습니다. 출력 검사와 조건 검사 API가 각각 프로그램을 컴파일하므로 명시적 컴파일
호출은1,296회입니다. 소스·기본 경로의 초기 유효성 검사도 별도로 수행됩니다.
위 숫자를 네이티브 실행 횟수로 세지는 않습니다.

정수 `9007199254740993`, `±9007199254740995`, `18014398509481990`를 포함합니다.
각 판단 입력의 의도·관측 구간은 그대로 보존했고, 첫 입력에는 아직 실행하지 않은
후보의 출력이나 실패를 넣지 않았습니다. v5의 적용 조건과 배열 구성은
[입력 설명](../../docs/semantic-value-flow.md)에 있습니다.

## 무엇이 달라졌고 무엇을 더 확인하나

이번 변화로 다섯 표현의 차이를 입력 단계에서 없앴습니다. 같은 모델과 같은 관측을
쓰면 이162개 소스 중 확인한 표현 쌍은 같은 판단 입력을 받습니다. 입력을 정리할 수
없는 프로그램은 기존 정보를 유지합니다. 범위가 넓은 프로그램의 동등성은 별도로
다뤄야 합니다.

이 실행의 학습·모델 호출·네이티브 실행은 모두0회입니다. 가중치는 새로 만들지 않았고
입력 일치 비율을 모델 정답률로 읽지 않습니다. 후속 학습을 위해 상수7·13의 직접 표현
16개를 학습 후보로, 같은 과제의 다른 표현64개와 다른 상수의80개를 나눠 기록했습니다.
그 학습은 이 기록에서 실행하지 않았습니다. 기존 v4 가중치와 과거 실험도 그대로입니다.

전체 명령은 벽시계0.69초, 사용자 CPU0.17초, 시스템 CPU0.11초, 최대 RSS35,717,120바이트였습니다.
평균 약0.41개 코어에 해당하는 명령 단위 비용이며 PC 전체 CPU 상승분은 측정하지 않았습니다.
데이터·파서·검사·기록 비용이 포함됩니다.

## 원본과 검산

`result/records.jsonl.gz`에는 모든 Gooo 소스, 변환된 계획, 두 입력 배열, 정리 이유,
후보별 결과와 통과 후보 집합을 보관합니다. 원본2.6MiB를 `gzip -n`으로 압축하고
해제한 바이트가 원본과 같은지 확인했습니다. 공개 파일의 해시는 `result/SHA256SUMS`에 있습니다.

```sh
go run ./studies/semantic-flow-normalization-20261010/audit \
  studies/semantic-flow-normalization-20261010/result
```

검산은 저장 기록만 읽습니다. 소스·계획·배열 해시, 정확한 정수, 사례 결과, 통과 후보와
쌍별 집계를 확인하며 새 컴파일·모델 판단·본문 평가를 추가하지 않습니다. 일반 CI에서도
이 검산을 실행합니다. 전체 SDK race·정적 검사와 별도 파서 템플릿 검사를 통과했습니다.
