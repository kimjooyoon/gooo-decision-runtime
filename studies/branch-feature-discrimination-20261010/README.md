# 분기 반환값이 모델 입력에서 사라지는 반례

2026-10-10. 컴파일러 CLI 연결 뒤, 더 다양한 기능으로 넓히기 전에 현재 입력 표현을
살펴봤다. 분기 특징이 산술 연산 종류를 기록하면서 직접 반환하는 값의 역할을 놓칠 수
있다는 가설을 세우고, 아래 두 Gooo 본문을 작성했다.

```text
if input < 10 { return 10 } else { return input }
if input < 10 { return input } else { return 10 }
```

두 소스 모두 같은 선택 의도를 적었다.
`Return the larger of the input and ten. 입력과 10 중 큰 값을 반환한다.`
선택은 분기를 그대로 쓰거나 뒤집는 두 가지이며, 출력 사례도 똑같다.

## 실제로 확인한 것

| 본문 | 사례 6개를 모두 만족하는 선택 | 현재 모델 제안 | 제안의 사례 통과 |
| --- | --- | --- | ---: |
| 위 본문 | 그대로, mask 0 | 뒤집기, mask 1 | 1/6 |
| 아래 본문 | 뒤집기, mask 1 | 뒤집기, mask 1 | 6/6 |

모델에 들어간 **256개 FP32 값, 총 1,024바이트가 완전히 같았다**.
원래 Gooo 소스와 계획은 서로 다르고 정답 선택도 반대다. 동일한 입력만 받는 결정론적
모델은 두 프로그램에 다른 첫 선택을 낼 수 없다. 이 두 반례를 같은 비중으로 보면
첫 선택은 최대 하나만 맞힐 수 있다. 이 수치는 전체 언어 정답률의 상한을 뜻하지 않는다.

실제 공개 모델도 두 번 모두 같은 점수와 같은 선택을 냈다. 판단 시간은12,916ns와
12,500ns였고 새 학습은0회다. 모든 후보4개를 각각 사례6개로 typed interpreter에서
확인했다. 정수 `-9007199254740995`와 `9007199254740993`을 그대로 사용했다.
이 실험의 네이티브 실행 횟수는0이다.
전체 명령은0.50초, CPU 사용자0.01초+시스템0.01초, 최대 RSS15,958,016바이트였다.
두 호출로 판단 속도를 일반화하지 않으며, 호스트 CPU 사용률 증가는 측정하지 않았다.

## 개발 방향에 주는 결론

다음 모델에서는 Gooo 분기의 반환값 역할을 입력에 담아야 한다. 우선 직접 반환하는
입력·상수·지역 변수와 연산 결과를 구별하고, 선택지를 뒤집었을 때 그 관계도 함께
표현하는 것이 필요하다. 변수 이름의 철자보다 어떤 선언의 값을 쓰는지가 중요하다.

기존 특징 배열은 ABI를 유지한다. 새 표현에는 별도 버전을 부여하고, 이 반례를 분리할 수
있는지 먼저 확인한 뒤 새 가중치를 학습하는 순서로 진행한다. 기존 공개 모델의 관측을
새 표현의 성적으로 바꾸지 않는다. 현재 컴파일러는 출력 사례로 잘못된 후보를 제외하고
남은 경로를 탐색할 수 있으므로, 모델 첫 제안의 한계와 조립 완성도를 구분해서 측정한다.
