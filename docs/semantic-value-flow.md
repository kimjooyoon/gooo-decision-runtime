# 같은 값 흐름을 다르게 적었을 때

v4는 소스 모양과 값 흐름을 함께 읽습니다. `return input`과 `result = input;
return result`는 반환값이 같아도 지역 변수·대입문 수와 반환식 모양이 다릅니다.
작은 모델이 이 차이를 매번 학습해야 하는 부담을 줄이기 위해 별도의 v5 입력을 추가했습니다.

`source_intent_condition_output_semantic_flow_v5`는384칸이며 기존 `flowdecision`의
9,290개 FP32 매개변수 구조를 사용합니다. `FitForFeatures`에서 이 버전을 명시해 새로
학습해야 합니다. 파일의 입력 버전과 모델 지문도 구분됩니다. 기존 v4 모델을 불러오면
기존 입력으로 동작합니다.

## 정리하는 범위

소스에서 하나의 분기를 확인하고, 양쪽 반환값과 비교 피연산자를 정확하게 추적할 수
있을 때 적용합니다. 선택지는 그 분기의 배치와 비교 피연산자의 순서에 한정됩니다.
복사한 값은 나중에 원래 변수에 다른 값을 넣어도 이전 값을 유지합니다. 분기 뒤에 있는
대입·복사와 최종 반환도 따라갑니다.

적용 여부는 `PreparedPlan.SemanticBranchContext(id)`로 확인할 수 있습니다.
`Normalized`와 `Reason`을 남기며 의도 문장·기대 출력·모델 점수를 읽지 않습니다.
중첩 분기, 다른 대입 대상/참조 선택, 확정하지 못한 값, 분기 외의 산술식 등은 원래
v4 배열을 유지합니다. 현재 판정은 단일 분기의 알려진 원자값에 대한 정리입니다.
일반 프로그램의 의미가 같다는 증명이나 후보 채택 권한으로 사용하지 않습니다.

| 입력 구간 | v5의 처리 |
| --- | --- |
|0–63| 선택 종류·결과 타입·비교 연산·선택 방향을 보존하고 지역 표기와 문장 수를 정리 |
|64–191| 원래 한영 의도를 그대로 보존 |
|192–235| 실제 관측한 조건 실패를 그대로 보존 |
|236–255| 해당 형태에서는 구문상의 반환 역할을 비우고255번 칸에2로 표시 |
|256–319| 실제 관측한 출력 실패를 그대로 보존 |
|320–383| 대입·복사를 따라간 두 반환값과 두 비교 피연산자의 정확한 정보 |

적용하지 않은 경우에는384칸 전체가 v4와 같습니다. 적용된 경우에는 분기 배치와
비교 순서 선택 모두에 값 흐름이 들어갑니다. 큰 정수는8개 바이트로 나누어 담으므로
정수 전체를 부동소수점으로 바꾸지 않습니다.

```go
input, err := prepared.InitialExecutionInput(cases)
// Handle err, then inspect the exact v5 input for one source-declared choice.
var features [384]float32
err = input.ExecutionSemanticFlowFeaturesInto("branches", &features)
```

`NewFlowSession`·`SearchFlowBatches`는 불러온 모델의 버전에 맞는 입력을 사용합니다.
이전 후보가 틀렸다면 저장된 관측을 다음 판단에 전달합니다. 모델이 없는 경로와 후보를
한 번씩 검사하는 탐색은 동일하게 유지합니다. 컴파일러 CLI의 v5 파일 연결은 후속 작업입니다.

## 확인 방법

단위 검사에서는 직접 반환·별칭·분기 대입·복사 뒤 덮어쓰기·분기 뒤 복사의 입력이
실패 관측 전후에 일치하는지 확인합니다. 정수 변경은 계속 구분하며 중첩 분기는 기존
입력을 유지합니다. 모델 세션이 실제로 새 배열을 소비하는지와 동시 요청도 검사합니다.

[Gooo 소스162개의 고정 계획](../studies/semantic-flow-normalization-20261010/protocol.txt)은
이 성질을 실제 파서·본문 실행으로 확인하기 위한 것입니다. 이 입력 버전의 학습 성적은
별도 새 학습으로 측정해야 합니다. 기존 모델과 실험 기록은 그대로 보관합니다.
